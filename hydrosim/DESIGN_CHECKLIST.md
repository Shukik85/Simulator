### □ Этап 2. Математическая модель кинематики

**Задача**: описать геометрию движений без учёта сил.

- [ ] 2.1 Выбрать систему координат и соглашения
  - 2D (плоская) или 3D модель
  - Направление осей, единицы измерения
- [ ] 2.2 Описать звенья как жёсткие тела
  - Длина, масса, центр масс, момент инерции
- [ ] 2.3 Решить прямую кинематику (FK)
  - По длинам ГЦ → координаты всех шарниров и кончика ковша
  - Уравнения: закон косинусов для треугольника OA-P
- [ ] 2.4 Решить 4-звенный механизм ковша (linkage)
  - Точки: A (ГЦ→рычаг), C (ось рычага), D (ось ковша), E (тяга→ковш)
  - Решение: геометрическое или численное (минимизация)
- [ ] 2.5 Решить обратную статику
  - По силе на ковше → усилия в штоках (принцип виртуальной работы)
  - Якобиан через конечные разности

  **Формулы**:
  ```
  θ = arccos((OA² + OP² − L²) / (2·OA·OP))   — угол звена по длине ГЦ
  J_ij = ∂x_i / ∂L_j                           — Якобиан (конечные разности)
  F_cyl = J^T · F_ee                           — виртуальная работа
  ```

### □ Этап 3. Математическая модель гидравлики

**Задача**: описать динамику давлений и расходов.

- [ ] 3.1 Модель насоса
  - Теоретический расход: Qth = Vd · n
  - Объёмный КПД (зависит от давления и износа)
  - Утечка в картер
- [ ] 3.2 Модель предохранительного клапана
  - Crack pressure, gain (m³/s/bar)
  - Режим stuck-open как fault
- [ ] 3.3 Модель open-center байпаса
  - Эквивалентная площадь, alpha = f(Ppump − PLS)
- [ ] 3.4 Модель золотниковой секции
  - Deadband, flow exponent
  - Orifice flow: Q = Cd·A·√(2·ΔP/ρ)
  - Расход P→A, P→B, A→T, B→T
- [ ] 3.5 Flow-sharing
  - Пропорциональное урезание расходов при нехватке насоса
- [ ] 3.6 Гидроцилиндр (диффуры)
  - dP = K/V · (Q − A·v − leak)
  - dv = (Ppiston·Apiston − Prod·Aannulus − Fext − Ffr) / m
- [ ] 3.7 Гидромотор поворота
  - Qm = D·ω, Thyd = ΔP·D
  - dω = (Thyd − Text − Tfr) / J
- [ ] 3.8 Интегрирование (RK4)
  - Шаг dt, клиппинг давлений/ходов/скоростей
- [ ] 3.9 Тепловая модель (опционально)
  - Потери насоса → нагрев масла
  - Охлаждение: dT = (η·P_loss − k·(T − Tamb)) / (m·Cp)

### □ Этап 4. Архитектура ПО

**Задача**: спроектировать код так, чтобы его было легко расширять.

- [ ] 4.1 Выбрать структуру модулей
  ```
  simulator/
  ├── core/          — типы, единицы, базовые утилиты
  ├── config/        — конфиги (датаклассы, JSON/YAML)
  ├── kinematics/    — чистые функции геометрии
  ├── mechanics/     — динамика (сборка кинематики + сил)
  ├── hydraulics/    — гидравлическая модель
  ├── faults/        — модель отказов
  ├── sensors/       — модель сенсоров (шум, дискретизация)
  ├── scenarios/     — сценарии работы
  ├── data/          — генерация и экспорт датасетов
  └── viz/           — визуализация (опционально)
  ```
- [ ] 4.2 Определить принципы
  - Stateless чистые функции для кинематики
  - Датаклассы для конфигов (не JSON-словари)
  - Внедрение зависимостей (config → model)
  - Разделение hydraulics (физика) и mechanics (геометрия)
- [ ] 4.3 Выбрать инструменты тестирования
  - pytest, hypothesis (property-based), golden tests
- [ ] 4.4 Выбрать формат конфигурации

- [ ] 5.1 Core

### □ Этап 6. Верификация и валидация

**Задача**: убедиться, что модель физически корректна.

- [ ] 6.1 Единичные тесты кинематики
  - На известной геометрии — известные углы
  - Проверка принципа виртуальной работы (F_cyl·dL = F_ee·dX)
- [ ] 6.2 Тесты гидравлики
  - Насос: Q(P) при разных rpm
  - Клапан: Qrelief(Ppump) — открывается после crack
  - Цилиндр: при подаче Q → движение с правильной скоростью
- [ ] 6.3 Законы сохранения
  - Материальный баланс: Qpump ≈ Qcyl + Qrelief + Qoc + leak
  - Энергия (качественно): мощность насоса ≥ механическая работа
- [ ] 6.4 Физические ограничения
  - Давление не превышает max relief
  - Ход ГЦ в пределах [0, stroke]
  - Скорости ограничены
- [ ] 6.5 Визуальная проверка
  - Анимация движений (опционально)
  - Графики давлений/расходов выглядят правдоподобно
- [ ] 6.6 Сравнение с эталоном
  - Если есть данные реального экскаватора — сравнить тренды
